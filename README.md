# Re:hear - 발표 훈련 서비스 (연습 완료 기록 · 진행률 추가)

발표 불안을 줄이기 위한 발표 훈련 서비스입니다. 기존 코드의 서비스 주제, 문구, id, 변수명, 함수명, 순서를 그대로 유지하고, **연습 완료 기록 및 진행률 자동 계산** 기능을 이어서 추가했습니다. 바뀐 곳은 코드 안에 `[추가]` / `[수정]` 주석으로 표시했습니다.

## 실행 방법

빌드 없이 `index.html`을 브라우저에서 열면 됩니다. (`logic.js` → `script.js` 순서로 로드)

## 파일 구성

| 파일 | 설명 |
| --- | --- |
| `index.html` | 화면 구조 (기존 구조 유지, 연습 구간·기록 영역 추가) |
| `style.css` | 스타일 (기존 유지, 연습 구간·기록·진행률 스타일 추가) |
| `script.js` | 화면 동작 (기존 구조 유지, 기록·진행률 연동 추가) |
| `logic.js` | **[추가]** 진행률 계산 등 DOM과 무관한 순수 함수 |
| `script.test.js` | **[추가]** `logic.js` 단위 테스트 |

## 사용 흐름

1. 발표 준비 설정: 테마, 발표자 이름, 녹음 활용 동의 → 동의해야 시작 버튼 활성화
2. 동의 안내 모달: 확인하면 설정 시작, 돌아가기/Esc 시 동의 해제
3. 1단계 정보: 발표 제목 입력 (비어 있으면 오류 메시지)
4. 2단계 조건: 발표 시간(3/5/10분), **연습할 구간(1개 이상 필수)**, 질의응답 포함·질문 수
5. 3단계 확인: 입력 요약, "수정하기"로 이전 단계 복귀
6. 4단계 기록: 연습을 마친 구간을 체크하면 완료 시각이 기록되고 진행률이 즉시 갱신
7. 다시 설정하기: 입력값, 선택값, 완료 기록, 진행률 모두 초기화

## 신규 기능: 연습 완료 기록 및 진행률

- 연습 구간: 도입, 본론 전개, 마무리와 요약, 목소리와 말 속도, 시선과 자세, 시간 배분
- 기록 대상 = 선택한 연습 구간 + (질의응답 포함 시) 질의응답 연습 1항목
- 진행률(%) = `완료 개수 / 전체 개수 × 100` (반올림, 0~100 보정, 전체 0이면 0%)
- 체크/해제 시 `n / m 완료 (p%)`, 진행 바, 안내 메시지가 `aria-live`로 갱신

## 과제 요구사항 대응

| 요구사항 | 구현 |
| --- | --- |
| 입력 | 텍스트(발표 제목), 슬라이더, 체크박스, 라디오, 이메일 |
| 상태 | 동의 여부에 따른 버튼 활성/비활성, 단계 표시, 선택 탭, 진행률 |
| 피드백 | 입력 오류 메시지, 완료 기록 메시지, 진행률 문구, 구독 성공 메시지 |
| 이전 단계 값 유지 | 이전/수정하기 이동 시 입력 요소 값을 지우지 않음 |
| 다시 시작 시 초기화 | `restartButton` 핸들러에서 formData, 입력 요소, 요약, 기록 화면 초기화 |
| 반응형 UI | 768px 이하에서 메뉴·탭·버튼 세로 배치, 요약 1열, 터치 영역 확대 |

## 테스트

```
node --test
```

수동 점검 체크리스트:

- [ ] 동의 전 시작 버튼이 비활성인가
- [ ] 발표 제목을 비우고 다음으로 가면 오류가 보이는가
- [ ] 연습 구간을 선택하지 않고 다음으로 가면 오류가 보이는가
- [ ] 3단계에서 수정하기를 눌러도 이전 입력이 유지되는가
- [ ] 체크할 때마다 진행률이 바뀌고, 해제하면 줄어드는가
- [ ] 다시 설정하기 후 모든 값과 기록이 비어 있는가
- [ ] 폭 768px 이하에서 레이아웃이 깨지지 않는가

## 기존 코드에서 고친 오류 (`[수정]` 주석 참고)

- `durationRang` 오타로 스크립트가 중단되던 문제 (`durationRange`로 통일)
- 진행 표시 클래스명 불일치 (CSS를 `progress_item`으로 맞춤)
- CSS 오타 `display: black`, `.has.error`
- 구독 메시지 스타일이 `@media` 안에만 있어 모바일에서만 적용되던 문제
